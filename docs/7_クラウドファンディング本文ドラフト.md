## こんな経験、ありませんか？

発売日の朝。狙っていたくじのために、少し早起きして家を出る。

1軒目のコンビニ。**完売**。
2軒目。**そもそも取り扱いがない**。
3軒目。ようやく見つけたけれど、**もう上位賞は残っていない**。

気づけば午後。交通費と、半日と、そして何より「楽しみにしていた気持ち」を消耗して帰る。

**この徒労、どうにかならないでしょうか。**

電話で聞けばいい——そう思ったこともあります。でも、レジに列ができている時間に「在庫ありますか？」と何軒も電話をかけるのは、お店にとって明らかに迷惑です。だから、聞けない。行くしかない。

そして実は、**この問題で困っているのはファンだけではありません。**

## お店も困っています

コンビニや書店のスタッフさんに話を聞くと、人気タイトルの発売日にはこんなことが起きています。

- 「在庫ありますか？」という電話が**繰り返しかかってくる**
- そのたびに手を止めて、売り場を確認しに行く
- レジが混んでいても、電話は鳴り続ける

**在庫を知りたいファンと、電話対応に追われるお店。両方が消耗している**のが今の状態です。

私たちがつくろうとしているのは、**この2つを同時に解決するサービス**です。

## つくるもの：一番くじの在庫が見える地図

『**くじレーダー**』（仮称）は、いま近くのお店にくじが残っているかを、**地図の色で一目でわかる**ようにするWebサービスです。

| 色 | 意味 |
| :--- | :--- |
| 🔴 **赤** | 完売 |
| 🟠 **オレンジ** | 品薄（残りわずか） |
| 🟢 **緑** | 在庫あり |
| ⚪ **グレー** | 情報なし |

**地図を開いた3秒後には、「どこに行けばいいか」がわかる。** それだけのサービスです。それだけのために、私たちは技術を使います。

## どうやって在庫を知るのか

「お店に聞かずに、どうやって在庫がわかるの？」

答えは、**すでにSNSに書かれている**からです。

発売日のX（旧Twitter）やInstagramには、毎分こんな投稿が流れています。

> 「【残数情報】A賞：0個 B賞：1個　残り16回です」（**お店の公式アカウント**）
> 「〇〇駅前のローソン、ラストワンまであと3枚だった！」（**ファンの投稿**）
> 「さっき補充されてくじ箱フルだったよ」

とくにお店の公式アカウントは、**残り本数もA賞の有無も、毎日きちんと発信しています。** 極めて新鮮で正確な在庫情報です。ただ、アカウントごとにバラバラに流れていくため、**「近所のどこにあるか」を知りたい人には届いていませんでした。**

**この投稿の山をAIが1件ずつ読み取り、「どの店の」「どういう状態か」に翻訳して、地図の上にプロットする。** これが『くじレーダー』の仕組みです。

### この発想は、金融の世界から来ています

株式市場には「**オルタナティブデータ分析**」という手法があります。公式発表を待つのではなく、SNS上の投稿をAIで解析して、市場の動きをいち早く推測する技術です。

**「バラバラのテキストから、現実の数値を推測する」**——この構造は、そのまま在庫推測に応用できます。私たちがやろうとしているのは、金融で実用化されている技術を、推し活の現場に持ち込むことです。

## 「AIの推測」だけに頼りません

正直にお伝えします。**SNSからの推測は、100%正確ではありません。**

投稿が古いかもしれない。店名が曖昧かもしれない。だから私たちは、次の3つを徹底します。

### ① 「なぜそう判断したか」を必ず見せます

どの投稿を根拠にその判定をしたのか、**元の投稿をそのまま表示します。** ブラックボックスにはしません。最後に判断するのは、あなた自身です。

### ② 複数の投稿が一致して初めて表示します

1件の投稿だけでは信用しません。**複数の投稿が同じことを言っているほど、確信度が上がる**仕組みにしています。確信度が低い情報は、そもそも地図に出しません。

### ③ 時間が経った情報は、自動的に消えます

在庫は刻々と変わります。**12時間を過ぎた情報は「情報なし」に戻ります。** 古い情報で空振りさせないためです。

## 最初のうちは、AIより「人の目」が主役です

ここは、いちばん正直にお伝えしたいところです。

企画にあたって、実際のSNS投稿を調べました。すると、**はっきりした傾向**が見えました。

| 投稿しているのは | 店名が分かるか |
| :--- | :--- |
| **お店の公式アカウント** | ほぼ分かる（残り本数もA賞の有無も書いてある） |
| **一般のファン** | **ほとんど分からない** |

ファンの投稿は「残り64枚だった！」とは書いても、**店名は書きません。** 自分がどこにいるかは、本人には分かりきっているからです。

つまり、**サービスを公開した直後は、SNSだけでは地図が埋まりません。**

### だから、電話確認から始めます

**公開初期の情報の正確さは、AIではなく、私たちの電話確認が支えます。**

主要エリアのお店には、スタッフが直接お電話して在庫を確認します。確認済みのお店には「**電話確認済み**」のマークが付き、地図上で優先的に表示されます。**これは推測ではなく、確定した情報です。**

### そして、使われるほどSNSの情報が育ちます

地図が使われるようになると、次のことが起きると考えています。

- 「あの店の在庫を知りたい」という**投稿そのものが増える**
- お店側も、**告知すればお客さまが来ると分かり、発信が増える**

**SNSの情報は、サービスが普及して初めて厚くなります。** 電話確認は、その立ち上がりまでを橋渡しする役割です。

**皆さまからの支援は、まさにこの「橋渡しの期間」を支えるために使わせていただきます。** 情報が薄いうちに人の手で品質を保てるかどうかが、このサービスが立ち上がるかどうかの分かれ目だからです。

### お店に迷惑をかけないための約束

ここは、このプロジェクトで**最もこだわっている部分**です。

「電話問い合わせを減らすサービス」が、自分たちで迷惑な電話をかけていては本末転倒です。だから、次のルールを徹底します。

- **架電するのは、クラウドソーシングの「プロクラウドワーカー」認定を受けた方のみ。** コミュニケーション評価4.8以上（5点満点）という基準をクリアした方だけにお願いします
- **通話は5秒で終える固定スクリプト**を使います
- **混雑する時間帯（昼休み・夕方）には絶対にかけません**
- **同じお店に何度もかけません**
- お店からのご意見を受け付ける窓口を設け、**1件でもご指摘があれば即座に対応します**

**私たちが1回電話することで、ファンの100件の電話がなくなる。** そういう仕組みを目指しています。

## 集めた資金の使い道

いただいた支援金は、**サービスを立ち上げ、最初の発売日を乗り切るために使います。**

| 用途 | 内容 |
| :--- | :--- |
| **SNSデータの取得費用** | X APIの利用料。**投稿1件を読むごとに約0.75円**かかる従量課金制で、人気タイトルの発売日には数万件の投稿が流れます。ここが最大の変動費です |
| **AI解析の費用** | 投稿を解析するAI（Google Gemini）の利用料 |
| **電話確認の人件費** | プロクラウドワーカーへの業務委託費 |
| **サーバー・地図の費用** | Webサイトの運用と地図表示のライセンス費用 |
| **開発・デザイン費** | アプリの開発と、お店向け管理画面の構築 |

> **なぜクラウドファンディングなのか**
> SNSデータの取得費用は、**使った分だけかかる従量課金**です。つまり、サービスを広げれば広げるほど費用が増えます。逆に言えば、**最初の数ヶ月を乗り切って利用者が増えれば、その先は自走できる**構造です。その「最初の数ヶ月」を、皆さんと一緒に越えさせてください。

## リスクとチャレンジ

このプロジェクトには、正直にお伝えすべきリスクがあります。

**① 在庫情報は「推測」であり、100%の正確性は保証できません**
SNS投稿をもとにした推測であるため、実際の在庫と異なる場合があります。表示には必ず「AI推測」であることを明記し、判断の根拠となった投稿も開示します。**このサービスは在庫を保証するものではなく、「行く前のあたりをつける」ためのものです。**

**② 公開初期は、SNSからの情報が少なくなります**
事前調査の結果、一般のファンの投稿には店名が書かれていないことが分かっています。**そのため公開直後は、地図の情報の多くを電話確認で埋めることになります。** 情報が載っているお店の数は、当初は限られます。利用者が増えるにつれてSNSの投稿量が増える見込みですが、**その立ち上がりが想定より遅れる可能性があります。** その場合は対応エリアを絞り、狭い範囲で密度を保つ方針で対応します。

**③ 外部サービスの仕様変更の影響を受けます**
X API・Instagram APIの料金体系や提供内容が変更された場合、対応エリアや更新頻度を調整する可能性があります。特にX APIは2026年2月に料金体系が変更されており、**今後も変更されうる前提で設計しています**。データ取得はすべて公式APIのみを使用し、規約に反する方法は一切行いません。

**④ 対応エリア・タイトルは段階的な拡大となります**
データ取得は従量課金のため、最初から全国・全タイトルには対応できません。**支援者の皆さまのリクエストと利用状況を見ながら、優先順位をつけて拡大します。**

**⑤ 開発の遅延**
開発は【　】が行います。想定外の技術的課題により、スケジュールが後ろ倒しになる可能性があります。その場合は活動報告にて速やかにご報告します。

**⑥ プロジェクトの継続について**
万一サービスの継続が困難になった場合も、支援者の皆さまへの状況報告を最後まで行います。返金対応については各プラットフォームの規約に準じます。

## 補足：この本文の設計意図

| お店の困りごとを早い段階で出す | 「ファンの利便性のため」だけだと共感層が狭い。**社会的意義に接続する**ことで、当事者以外の支援も得られる |

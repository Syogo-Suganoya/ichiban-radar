## 0. この事業の収益構造上の急所

### 良い点：ユーザーが増えてもコストが増えない

X APIの費用は**ユーザー数ではなく「監視範囲（対象エリア × 対象タイトル数）」に比例**します。1万人が見ても10万人が見ても、収集する投稿数は変わりません。Instagramは無料、Gemini解析費も投稿数に比例するだけです。

つまり**ユーザー1人増えたときの追加コストはほぼゼロ**。分岐点を超えた先の売上はほぼそのまま利益になります。

### 課金できる相手がいる（第3版で復活）

**ログインは任意**です。未ログインでも地図・店舗詳細・A賞フィルタは使えます。ログインで増えるのは次の2つだけで、これがプレミアムプランの中身になります。

1. **お気に入り店舗の登録**（登録店舗だけに地図を絞り込める）
2. **在庫急変のプッシュ通知**（品薄・完売・上位賞が消えた瞬間）

**無料機能を人質に取らない**ことが要点です。「地図が見たいだけの人」は登録せずに使えるので離脱せず、母数は広告で回収します。課金するのは「特定の店を張っている熱量の高い層」だけです。

## 1. 収益モデル（改訂後）

| 収益源 | 位置づけ | 規模感 |
| :--- | :--- | :--- |
| **① 広告** | 未ログイン層を含む全員から薄く回収する土台 | 1人あたり月 **約2.4円** |
| **② プレミアムプラン** | **収益の主柱**。月額390円 / 年額3,900円 | 有料会員1人 **約376円**（決済手数料差引後） |
| **③ B2B（店舗掲載枠）** | 安定収益。景気に左右されにくい | **月1〜3万円/店舗** |
| ④ アフィリエイト | 上乗せ。**本サービスとは相性が限定的** | 1人あたり月 **約0.1円** |

> **有料転換1人＝無料ユーザー約160人分**の収益です。広告を主軸に据えるのは誤りで、プレミアムへの転換が事業を支えます。

### ④の相性が悪い理由

利用者は「**いま近くの店で買いたい**」人で、通販で買いたい人ではありません。この動機のズレがあるため、通販アフィリエイトのコンバージョンは構造的に低く出ます。**上乗せとしてのみ数えてください**（詳細は[8_広告・アフィリエイト実装ガイド](8_広告・アフィリエイト実装ガイド.md)）。

### 提供機能

| 機能 | 未ログイン | **プレミアム（月390円）** |
| :--- | :---: | :---: |
| マップ閲覧・在庫ステータス表示 | ○ | ○ |
| 店舗・タイトル検索 | ○ | ○ |
| 「A賞あり」での絞り込み | ○ | ○ |
| 判定根拠となった投稿の開示 | ○ | ○ |
| **お気に入り店舗の登録・絞り込み** | — | ○ |
| **在庫急変のプッシュ通知** | — | ○ |
| **上位賞が無くなった通知** | — | ○ |

## 3. B2B（店舗掲載枠）

| メニュー | 想定単価 | 内容 |
| :--- | :--- | :--- |
| **店舗掲載枠** | **月1〜3万円/店舗** | アニメショップ等の在庫情報を優先表示＋店舗ページへの導線 |
| 入荷情報の自社入力 | 月額 | 店舗自身が入荷情報を入力できる管理画面の提供 |
| メーカー向けデータレポート | 個別見積 | エリア別の消化速度・完売までの時間などの集計 |

**「電話問い合わせを減らす」という店舗側の課題解決とセットで提案できる**ため、単なる広告枠より訴求しやすい構造です。ユーザー数に依存しない安定収益なので、**プレミアムが伸びない場合の保険**にもなります。

| 前提 | β版（月91,000円）の分岐点 |

## 5. 収益性を改善する打ち手

**① コストを下げる（最も確実）**

X APIは**監視範囲に比例**するので、対象エリアとタイトルを絞ればそのまま下がります。**赤字なら自動的にコストを下げられる**のがこのモデルの利点です。オペレーターの稼働も大型発売日のみに集中させれば月2万円程度まで圧縮できます。

**② B2Bを取りに行く**

5店舗（月10万円）で β版のコストを丸ごと賄えます。**MAU 9,000を集めるより、店舗を5社取る方が早い**可能性は高く、両方を並行して進めます。

**③ 有料転換率を上げる**

**プレミアムは「プッシュ通知が動くこと」が価値の核**です。通知が来ない状態で課金しても価値を感じられず、すぐ解約されます。
通知の質（＝「行動が変わる変化」だけに絞る）を守ることが、そのまま転換率と継続率になります。

## 6. 収益化ロードマップ

| フェーズ | 施策 | 目標 |
| :--- | :--- | :--- |
| **Phase 1（PoC）** | 収益化しない。精度検証に専念 | 店舗特定率の実測 |
| **Phase 2前半（β版）** | 独自ドメイン・プライバシーポリシー整備 → **AdSense申請** | MAU 5,000 |
| **Phase 2後半** | **プレミアムプラン開始**（プッシュ通知の実装完了が条件）＋ **B2Bの営業開始** | **MAU 9,000 または 契約5店舗＝単月黒字** |
| **Phase 3（本運用）** | 全国・全タイトルへ拡大。アフィリエイト・メーカー向けレポート | 投資回収完了 |

### クラウドファンディング支援者の扱い

プレミアムプランが復活したため、**「プレミアム長期利用権」をリターンに使えます。**

短期的には課金収益の機会損失ですが、支援者は**サービス初期から使ってくれる層**であり、通知機能のフィードバックを最も早くくれる相手でもあります。**初期の改善速度を買うコスト**として整理し、上記試算の有料会員数には含めません。

## 7. リスクと対策

| リスク | 内容 | 対策 |
| :--- | :--- | :--- |
| **有料転換が伸びない** | プッシュ通知の価値が伝わらないと課金されない | **通知が動くまでプランを出さない**。広告オフのような弱い訴求で先行販売しない |
| **解約されやすい** | 発売サイクル型のため「欲しいくじがない月」に解約されやすい | **年額プラン（2ヶ月分お得）を主導線に**／発売カレンダー通知でオフシーズンの接触を維持 |
| **転売関連広告の混入** | サービスの信頼性と権利者との関係を同時に毀損する | **カテゴリブロックを必須運用**とし、月1回は実配信広告を目視確認（[8_実装ガイド](8_広告・アフィリエイト実装ガイド.md) 3-1） |
| **ステマ規制違反** | 景品表示法。アフィリエイト導入時に「PR」表記が必要 | [8_実装ガイド](8_広告・アフィリエイト実装ガイド.md) 4章のとおり実装する |
| **AdSense審査に落ちる** | 地図アプリ単体は「コンテンツが少ない」と判断されやすい | LP＋説明ページ＋FAQを用意してから申請する |
| **商標・権利者との関係** | 「一番くじ」はBANDAI SPIRITSの登録商標。広告収益化で関係リスクが顕在化 | サービス名に商標を含めない／非公式である旨を明記／収益化開始前に表示方法の照会を検討 |
| **アドブロック** | 広告収益の目減り | B2Bはアドブロックの影響を受けない |

## 8. アクションプラン

1. **独自ドメインの取得**とプライバシーポリシー・運営者情報・問い合わせ窓口の整備（AdSense申請の前提）
2. **AdSense申請**（[8_広告・アフィリエイト実装ガイド](8_広告・アフィリエイト実装ガイド.md) 5章）

6. β版リリース後、**実際のDAU/MAU比率・eCPM・有料転換率を実測**し、本計画の前提を差し替える
7. **プッシュ通知の実装完了を、課金開始の前提条件として管理する**
